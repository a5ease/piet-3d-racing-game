一个「决策全部写在 Piet 程序图片里」的 3D 赛车 demo。Python 只扮演 Piet 的"手"：
执行解释器（VM）、读写窗口/键盘、把 Piet 算好的数值渲染成像素。**所有游戏逻辑
（玩家位置、速度、碰撞、圈数、生物群系、相机姿态）均由 Piet 指令在运行时算出。**

## 技术亮点

**Piet 是什么？** 一种极度深奥的编程语言（esolang）：程序不是文本，而是一张由色块组成的**图片**。解释器从左上角出发，沿方向逐块移动，靠**两种颜色的 RGB 色差**决定执行哪个指令——而它只有一个栈、没有变量、没有函数、没有循环语句。

**这个项目难在哪？**

- **没有函数与变量，只有一张栈 + 一个 DP/CC 指针**：所有游戏逻辑（速度钳位、碰撞判定、生物群系、相机姿态）都要用纯栈公式硬推出来。
- **指令由颜色生成**：写"程序"= 把 RGB 像素排布成特定几何形状，一个整数要拆成十进制逐位参与，块宽必须≤10，否则跨行会改变转弯语义。
- **蛇形布局 + 黑墙转弯**：代码按蛇形铺在 1803×1803 的画框里，偶数行左→右、奇数行右→左，用黑墙保证转弯几何完全确定。
- **数学全用整数硬算**：Piet 没有浮点。`sin` 用定点 + Taylor 三阶多项式，`π` 用 `MOD` 归约 + 象限折叠；伪随机用线性同余（LCG）现场生成——全部 `DIVIDE/MOD` 整数实现，误差 ≤1%。
- **没有「循环」，用学习式跳转**：Piet 无法写循环，这里用 `EXT_SKIP_IF` + `EXT_FRAME_START` 实现"首帧记录块位置，后续帧机械跳转"的守卫分支。
- **决策真源 = 一张图片**：`game_core.png`（45 万+ 色块）从编译期就决定了所有世界数据与规则，Python 只做"解释执行 + 渲染"，运行时零游戏决策。

**成果**：不止跑得起来，而且有 OpenGL 3D 渲染、HUD 仪表（速度表/转速盘/计时板/小地图）、多生物群系赛道、叶子等粒子特效，单帧保持在 **60fps 目标**内。

## 玩法

| 按键 | 作用 |
|---|---|
| `←` / `→` | 左右转向 |
| `↑` / `↓` | 加速 / 减速 |
| `Esc` 或窗口关闭 | 退出 |

HUD：速度表、转速盘、计时板、小地图；赛道上会经过多种生物群系（城市 / 沙滩 /
山地等），需避开树木与建筑。

## 运行环境

- Python 3.8+（推荐 3.11），Windows / macOS / Linux
- 依赖见 `requirements.txt`，国内可用清华镜像安装：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 启动

```bash
python run_game.py
```

启动时会重新生成 `game_core.png`（Piet 程序本体，45 万 + 色块）并保留上一版
创作区的绘画，然后进入游戏主循环。

## 程序结构

| 文件 | 作用 |
|---|---|
| `racing_game.py` | 引擎主体：Piet 汇编器、Piet 解释器、OpenGL 渲染器、HUD |
| `piet_asm.py` | Piet 汇编标准库（定点 sin、LCG、循环/分支宏） |
| `paint_core.py` | program 图创作区作画的辅助工具（人工绘制） |
| `run_game.py` | 一键启动入口 |
| `game_core.png` | 生成的 Piet 程序本体（决策真源） |

> 所谓「纯 Piet 驱动」，指上图这张 1803×1803 的程序图：以下 `game_core.png` 就是游戏逻辑的"源代码"——跑起来时，解释器逐色块执行里面的指令，游戏的一切决策都在这张图片里算出

![Piet 程序本体（决策真源）](game_core.png)

## 调试环境变量（自动化验证用，慎用）

| 变量 | 作用 |
|---|---|
| `PIET_FORCE_2D=1` | 强制软件光栅(2D)通道（无 OpenGL 时的回退） |
| `PIET_SEEK_Z=<整数>` | 跳转到指定赛道位置 |
| `PIET_DEMO_STEER=1` | 自动模拟转向，用于无头截图验证 |

`痛苦旅程/` 下的 `verify_*.py` / `smoke_*.py` 是里程碑回归脚本，供开发验证。
